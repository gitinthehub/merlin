# 2.10 — the story picker (what the plan must cover)

The requirement in the owner's words: *"let the user choose between different stories at the
beginning."* The engine and the page need these properties; propose the cleanest implementation,
but keep every one of them:

- **A registry, not a hard-wired bundle.** `arcs/last-signal.js` and `arcs/pale-hand.js` are both
  built by `tools/build-arc.js`, and `renderBundle` currently assigns `root.OronathArcBundle = api`,
  so loading two bundles silently overwrites the first. The build must additionally register each
  arc under its own id (`root.OronathArcBundles[api.id] = api`) **while keeping the existing
  `OronathArcBundle` assignment** — `tests/last-signal.test.js` asserts that literal string and the
  single-arc fallback path depends on it. Any change to `renderBundle` means both committed bundles
  must be re-derived by the tool in the same pass, and the committed `.js` must be byte-identical to
  a fresh `bundleFromFile` of its `.json` (that will become a test assertion).
- **A small registry module** (`stories.js`, new; plain IIFE, `window.OronathStories`, and the same
  UMD tail as `dice.js`/`arc.js` so a Node test can `require` it) that lists the registered arcs
  with `{id, title, blurb, pitch, chapterCount, cast, arc}` and can report the arc that the single
  save slot belongs to. It must read the save **through `OronathPersist.SAVE_KEY`** and must never
  clear or rewrite it — `persist.js` is frozen, so the save's arc id has to be peeked, not
  fetched through a changed API. Report what `persist.js` does today when the save belongs to a
  different arc (`blob.arcId !== arc.id` → reject + `clear()`), and make sure the picker's flow
  cannot silently destroy a resumable run of the other story.
- **The surface** `oronath-ui.js`: when two or more stories are registered, the first screen is the
  picker (each story: title, one-line blurb, chapter count, cast names, a `Begin` button, and
  `Resume — Chapter N` when the save belongs to that arc); picking one goes to that story's existing
  splash (title, pitch, cast with traits, `Begin`). When only one arc is registered (or only the
  sample fallback), behaviour must stay as it is today. An in-progress save that matches a
  registered arc still resumes straight into the run, exactly as now (the browser playthrough
  notes in `.qa/` and the repo's own docs describe that behaviour as correct). Validation errors
  still block play and are shown per story.
- **The run must be created from the arc's own cast.** `Loop.createRun(arc)` with no options falls
  back to `Cast.pregen("john"|"joel"|"rafe")`, which for `pale-hand` would produce characters whose
  ids are `john`/`joel`/`rafe` and then throw `unknown actor: jin` on the first choice. The surface
  must pass `{characters: Story.characters}`. Say explicitly in the plan whether that changes
  anything for `last-signal` (its bundle already carries expanded characters).
- `oronath.html` loads both bundles plus `stories.js` in a working order; `index.html`'s splash link
  to `oronath.html` stops naming one story; `oronath.css` may grow story-card styles (`style.css`
  may not change).
- No ES modules, no `package.json`, no bundler, no runtime network request: the page must keep
  working opened from `file://`.
