## 3. REGISTRY API AND PICKER BOOT FLOW

`renderBundle` keeps the singular assignment so [tests/last-signal.test.js](tests/last-signal.test.js) and a page with one bundle still work. Loading both scripts means `window.OronathArcBundle` is whichever script ran last (Pale Hand, if the tags are in the order below). The UI must not treat that singular global as the only story once `list().length >= 2`.

Script order in [oronath.html](oronath.html), all plain `script src`, no `type=module`, so `file://` still works: `dice-view.js`, `dice.js`, `arc.js`, `characters.js`, `sample-arc.js`, `arcs/last-signal.js`, `arcs/pale-hand.js`, `loop.js`, `persist.js`, `stories.js`, `oronath-ui.js`.

`stories.js` reads `root.OronathArcBundles`, `root.OronathArcBundle`, `root.OronathSample`, and `root.OronathPersist` at call time, not at load time. If `OronathPersist` is missing it `require`s `./persist.js`, the same lookup pattern [persist.js](persist.js) uses for the loop. The save key is `persistApi().SAVE_KEY`. The module never calls `setItem`, `removeItem`, `Persist.save`, `Persist.load`, or `Persist.clear`.

API:

- `list()` — registration order (script order: Last Signal, then Pale Hand). Each entry is `{ id, title, blurb, pitch, chapterCount, cast, arc }`. `chapterCount` is `arc.chapters.length`. `cast` is the character `name` strings in array order. `blurb` and `pitch` are the arc fields or `""`.
- `get(id)` — that entry, or `null`.
- `fallback()` — `root.OronathArcBundle` if set, otherwise `root.OronathSample`. Used only when `list()` is empty. The sample is not a third card when any bundle is registered.
- `savedArc(storage)` — the ready object below, or `null`.
- `saveStatus(storage)` — `"empty"`, `"ready"`, `"foreign"`, or `"unusable"`.

A ready object is `{ arc, arcId, nodeId, phase, chapterNumber, chapterTitle }`. `chapterNumber` is the 1-based index when `nodeId` is a chapter, and `null` when `nodeId` is an ending. `savedArc` returns that object only when the blob would already pass `Persist.load` for that arc: JSON object, `version === Persist.VERSION`, `arcId` equal to a registered id, `rng.a` a number, phase `choose` or `outcome` or `resolved`, `nodeId` a chapter or ending of that arc, `history` and `diceLog` arrays of equal length, and an outcome blob with `result.faces` and `consequence` when the phase is `outcome`. Anything else is `null`.

`saveStatus` distinguishes the nulls. Empty or missing storage is `"empty"`. A parsed version-1 object whose `arcId` is not registered is `"foreign"` (include that `arcId` on the report object the UI can ignore). Bad JSON, a version other than 1, or a registered `arcId` whose shape would make `load` reject is `"unusable"`. `"ready"` matches `savedArc`.

Boot, in [oronath-ui.js](oronath-ui.js). Screen is `picker`, `splash`, or `play`. `active` is the arc those renders read.

- Zero registered arcs. `active = fallback()` (sample, or the singular bundle if a test left one). Today's boot: `Arc.validateArc(active)`, then `Persist.load(active)`, which may clear a foreign or broken slot. Success resumes straight into the run. Any other non-empty reason sets `Saved run could not be resumed.` and shows the splash. No picker. This is the one-arc and sample path, including a page that loads only `arcs/last-signal.js`.
- One registered arc. Same function, with that arc. No picker. `createRun(active, { characters: active.characters })` on Begin.
- Two or more, and `savedArc()` is ready, and `validateArc` on that arc is clean. `Persist.load(saved.arc)` and go to `play`. This is the refresh-resumes-mid-chapter behavior the QA notes treat as correct. `load` is safe here because `savedArc` already applied `load`'s accept checks, so `load` will not `clear()`. If `validateArc` fails, do not enter the run. Show the picker with that card's errors and Begin disabled.
- Two or more, and `savedArc()` is null. Screen is `picker`. Do not call `load`. Do not clear. `"foreign"` shows `A saved run for another story is still stored.` `"unusable"` shows `Saved run could not be resumed.` `"empty"` shows no note.

Picker card, one per `list()` entry: title, one-line blurb, `N chapters`, cast names, a `Begin` button. When `savedArc()` is ready and `saved.arcId === entry.id`, also `Resume — Chapter N` if `chapterNumber` is set, or `Resume` if the slot is already on an ending. Validation errors for that arc render on the card. `Begin` and `Resume` are disabled while that arc's `validateArc` is not ok. The other card still works.

- Card `Begin` sets `active` and opens that story's splash. It does not clear and does not create a run.
- Card `Resume` calls `Persist.load` on the saved arc and enters `play`.
- Splash is today's title screen for `active`: kicker, title, `active.pitch` when it is non-blank, otherwise the sample sentence or the Last Signal sentence already in `renderTitle`, then cast names with trait labels, then `Begin`. Errors still replace `Begin`. When two or more stories are registered, the splash also has `All stories`, which returns to the picker and does not clear.
- Splash `Begin` is today's `startFresh`: `Persist.clear()`, then `Loop.createRun(active, { characters: active.characters })`, then save, then `play`. That clear is the player's Begin, after they have seen Resume on the other card if the slot was theirs. It is the only multi-arc path that erases the slot.
- During `play`, with two or more stories, a `Stories` button sets `run` to null and opens the picker. It does not call `clear`. The last `Persist.save` is still in the slot, so the matching card shows `Resume — Chapter N`. `New Run` still clears. With two or more stories it returns to the picker. With one story it returns to that splash, as it does now.

`threadList`, `nextLabel`, and the roll blurbs read `active`, not a global captured at parse time. A resumed Last Signal run must show John, Joel, and Rafe's threads.
