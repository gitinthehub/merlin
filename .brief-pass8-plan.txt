## The product spec the arc pipeline must satisfy

- **Complete story arcs are pre-generated BEFORE gameplay begins** — not improvised turn by turn. Generating an arc at runtime, in the browser, per player, is explicitly not what is wanted.
- An arc is **3–5 chapters**; each chapter has a setting description, a core objective, **2–4 branching choices**, and clear success/failure consequences for each.
- **All character arcs must resolve by the end — no loose threads.** The validator already enforces this; a generated arc that fails validation must never reach a player.
- The tone is cinematic, vivid, specific, visual, with clear cause → effect → consequence and no vague resolutions.
- The seed arc the owner supplied, for reference: **"The Last Signal of Oronath"** — John (stealth, night vision, endurance; arc: memory/identity), Joel (strength, an axe with unknown carvings; arc: legacy), Rafe (speed, sniper, alien origin; arc: return-home). Four chapters: **The Signal Tree** (retrieve a pulsing crystal from an 80-foot dead tree with glowing blue veins), **The Echo Field** (illusions built from memory; John's past is triggered; navigating truth vs illusion), **The Axe Lock** (Joel's axe carvings match a hidden vault; decode and align; failure triggers guardians), **The Signal Core** (an alien device tied to Rafe's origin; final choice: destroy it, activate it, or use it as a portal).

## The constraint that shapes 2.6

The site is **static and keyless**: no server, no API keys in the client, no runtime network requests. So "arc pre-generation" must happen **off the player's machine**, and the built artefact must be a plain JS file the static page loads like any other script.

Decide and write down how the pipeline works, covering at minimum:
- **A provider call path** for generating an arc: a local Node script that takes an API key from an **environment variable** (never committed, never in the client), sends the schema and the spec above, and receives a whole arc as JSON. Name the provider(s) it supports and how it is configured. Treat a missing key as an expected condition with a clear message, not a crash.
- **A keyless path that must exist**: the same tool must be able to accept an arc **from a file** — authored by hand or by an agent that already exists in the workflow (Cursor itself, or the owner's Grok Bot app) — and validate, repair-report and bundle it without any API call. This is how 2.8 will actually be produced, so it is not optional.
- **Validation before bundling, always**: the generated or supplied arc goes through the 2.2 validator; on failure the tool reports every rule violation by path and either retries with the errors fed back or refuses to write an artefact. An invalid arc must never be written into a loadable file.
- **The bundled artefact**: a plain IIFE JS file assigning to a `window.*` global, loadable by `oronath.html` with a `<script>` tag, that the loop can run exactly as it runs `sample-arc.js`.
