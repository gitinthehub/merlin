## The product spec these modules must satisfy (verbatim requirements)

**Dice system — mandatory, must be implemented as real logic, not prompted behaviour:**
- **d20** → main skill checks, difficulty-scaled: Easy 8+, Medium 11+, Hard 14+, Very Hard 16+.
- **d10** (0–9, or 00 = 10) → reaction speed, precision timing, chaos checks.
- **2d6** → strength, teamwork, physical force, damage.
- Critical outcomes: natural 1 / lowest roll → **major complication, not a simple failure**; max roll → bonus success or story advantage.
- Every meaningful action requires a roll. **Failure must create a new consequence/branch, never a "try again".**

**Story structure:**
- Complete story arcs are **pre-generated before gameplay begins** (not improvised turn by turn).
- Each arc is 3–5 chapters. Each chapter has: a setting description, a core objective, 2–4 branching choices, and clear success/failure consequences for each.
- **All character arcs must resolve by the end of the story — no loose threads.**
- Tone: cinematic, vivid, specific, visual; clear cause → effect → consequence; no vague resolutions.

**Characters:** stats/traits tied to arcs, and a character's traits modify roll difficulty (the "advantage due to build" pattern).

## Task — plan these three deliverables

**2.1 `dice.js` — core dice engine.** d20 / d10 / 2d6 as standalone, testable functions; the four difficulty tiers; crit rules including "lowest roll is a major complication rather than a plain failure"; advantage and per-character advantage. Zero UI coupling and zero LLM coupling. RNG must be injectable so tests are deterministic (and so 2.6 can seed a run later).

**2.2 Arc schema + validator.** The data shape `arc → chapters(3–5) → choices(2–4) → consequences`, plus a validator that **rejects** an arc with: a dangling/unreachable branch, a missing success or failure consequence, a chapter count outside 3–5, a choice count outside 2–4, or a character thread left unresolved at the end. Validation happens **before** play.

**2.3 Character system.** Stats/traits attached to arcs; traits that modify roll difficulty and can grant advantage ("advantage due to build"); per-character arc threads that the validator requires to resolve by the final chapter. Include the three Oronath pregens as the worked example in the schema: **John** (stealth, night vision, endurance; arc: memory/identity), **Joel** (strength, an axe with unknown carvings; arc: legacy), **Rafe** (speed, sniper; alien origin; arc: return-home).

**Tests.** A zero-dependency test harness for 2.1–2.3, runnable with a plain `node tests/<file>.js` (no `package.json`, no packages) and also loadable in a browser. Table-driven cases for the dice engine (every tier boundary, every crit boundary, advantage keep-best with injected RNG, d10's 0/00=10 case, 2d6 distribution shape) and for the validator (one valid arc accepted; one deliberately broken arc per rejection rule).
